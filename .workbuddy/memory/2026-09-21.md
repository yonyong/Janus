## Janus 打包为 Windows 桌面应用（exe + 图标）

用户要求把平台打包成带图标的桌面应用 exe。确认方案：**pywebview 原生窗口 + PyInstaller onedir + 重绘图标**。

### 新增 / 改动
- `assets/janus-icon.svg`（新）：1024×1024 矢量源，沿用 favicon 的蓝紫渐变圆角方块 + 白色 J
- `tools/make_icon.mjs`（新）：sharp 渲染 16/24/32/48/64/128/256，再用纯 Node 二进制拼 ICO
  → 产出 `assets/janus.ico`（19KB，7 帧）+ `assets/janus-512.png` 预览
- `pack_launch.py`（重写）：webbrowser 开浏览器 → pywebview 原生窗口；另补动态端口、单实例互斥、
  可写目录回退（装到 Program Files 时退到 LOCALAPPDATA）、日志落文件、失败弹窗
- `pack.bat`（重写）：图标生成 → 依赖安装 → 前端构建 → PyInstaller 打包；文件加 UTF-8 BOM 防 cmd 中文乱码
- `requirements.txt`：加 pywebview

### 踩到的坑（复发风险高）
- **PyInstaller 6.x 的 onedir 把 `--add-data` 资源全塞进 `dist/Janus/_internal/`（= sys._MEIPASS）**，
  顶层只剩 Janus.exe。启动器必须区分 RES_DIR（_MEIPASS，只读资源）与 APP_DIR（exe 旁，可写数据），
  否则前端挂不上、数据库写不进。原 pack_launch 里的 `APP_DIR/web/dist` 是错的。
- config.py 的 BASE 打包后指向临时解压目录 → 读不到 .env → 管理员令牌**静默退化成开放模式**。
  已在 `_apply_paths()` 补读 exe 旁 .env（外部优先，回退内置）。
- pip 的清华镜像不可达；`--index-url https://pypi.org/simple` 直连正常。
- PyInstaller 覆盖旧 dist 会被 safe-delete 拦（305 文件 > 50 阈值）：用 `mv dist/Janus dist/_tmp` 绕过再打包。

### 验证结果（dist/Janus，44MB）
- 原生窗口创建成功，窗口标题「Janus · AI 原生开发平台」
- exe 资源：RT_ICON 7 帧 / RT_GROUP_ICON 1 / RT_MANIFEST 1 ✅
- 8000 被 `0.0.0.0` 占用时自动顺延到 8001；前端 js/css/api 全部 200
- 二次启动被命名互斥体拦截并唤起原窗口，进程数保持 1

### 遗留
- `.env` 内置令牌仍是 `123456`，发布前需替换
- 目标机器需 WebView2 运行时（Win10 1803+ / Win11 通常自带）
- `tsc` 报 `RequirementList.tsx:309` 类型错误（并行工作流引入，与打包无关，未处理）

## 配置外置到 exe 同级 config.ini（需求追加）

用户要求：关键配置（端口、管理员口令等）必须放在 exe 同级的 `config.ini`，而不是内置进 exe。
**取代上面的「内置 .env」方案**——`.env` 不再打包，避免出现两个配置源。

### 改动
- `pack_launch.py` 新增配置层：
  - `_ini_template()`：带中文注释的默认配置（`[server]` port/host、`[admin]` password、
    `[share]` public_base_url/public_port、`[log]` level）
  - `_ensure_config_ini()`：不存在则生成；口令取「exe 旁 .env 迁移值」或随机 `janus-xxxxxxxx`
  - `_apply_ini()`：落到 CONFIG 对象 + `os.environ`（不覆盖已存在的环境变量），
    后者让 `public_share_base()` 这类运行时读 env 的逻辑也能生效
  - 用 `configparser(interpolation=None)`：口令里含 `%` 不会被当成插值语法而报错
- `tools/make_config_ini.py`（新）：打包收尾生成现成 config.ini，已存在则跳过、不覆盖用户改动
- `pack.bat`：去掉 `--add-data ".env;."`，流程改为 5 步（末尾加「生成配置模板」）

### 配置优先级
`config.ini` > 进程环境变量 > exe 旁 `.env`（仅首启迁移用）> `config.py` 内置默认

### 验证（dist/Janus）
- 首启自动生成 config.ini，口令 `janus-7958c494`（本机装完包没有 .env 可迁移 → 取随机值）
- 改成 `port=8123` / `password=my-secret-admin` 后重启：
  - 服务确实监听 8123，根路径 HTTP 200
  - `/api/admin/verify?admin=my-secret-admin` → **200**
  - 旧随机口令 → 401；**原内置口令 123456 → 401**（证明配置已完全由 config.ini 接管）
- 二次执行 `make_config_ini.py` 不覆盖已存在文件 ✅

### 注意
- 管理员口令走 **query 参数 `admin`**，不是 HTTP header
- 重新打包时 `dist/Janus` 可能被残留 shell 的 cwd 锁住（报 `Device or resource busy` 后变
  `Permission denied`）：此时要清空目录**内容**而不是改名整个目录。后台任务里 `cd dist/Janus`
  会把该目录锁住——跑完记得先 `taskkill` 再切走工作目录

## 修正：浏览器里选目录不该走 webkitdirectory（改成后端列目录）

用户反馈：在 Edge 浏览器里点「浏览」弹出「将 800 个文件上传到此网站？」确认框。

### 根因
纯浏览器出于安全沙箱无法读取本地绝对路径，`<input webkitdirectory>` 的机制就是让网页
枚举整个目录的文件并"上传"，因此必然弹那个确认框，且只能靠非标准 `file.path` 勉强还原路径。

### 改动（取代上一节的 webkitdirectory 兜底）
- 后端新增 `GET /api/admin/fs/dirs`（`backend/app.py`，`Depends(require_admin)`）：
  - 不传 path → 返回盘符列表（`_drive_roots()`，Windows 扫 A-Z 存在的盘，非 Windows 返 `['/']`）
  - 传 path → 返回该目录的子目录 + 上级目录；路径不存在 400、非目录 400、无权限 403
  - 只列目录、不读文件内容；统一正斜杠
- 前端：
  - `web/src/components/DirPickerModal.tsx`（新）：网页版目录选择器（盘符列表 / 上下级导航 /
    路径输入跳转 / 「选择此目录」按钮）
  - `api.ts`：`adminListDirs(path)` + `DirListing/DirEntry` 类型（走 `adminUrl` 自动带 `?admin=`）
  - `FolderPathInput.tsx`：桌面仍走 pywebview 原生对话框，其余改弹 `DirPickerModal`，
    彻底移除 `webkitdirectory` 那套
- `tools/smoke_fs_dirs.py`（新，端口 8034）：HTTP 冒烟 16 项断言全通过

### 验证
- `tools/smoke_fs_dirs.py` 16/16 PASS；`backend/tests/run_all.py` **283/283 passed**
- `vite build` 成功（web/dist 已更新）；tsc 仍只有 `RequirementList.tsx:309` 预存错误
- 注意：8000 端口在跑的后端是旧进程（新接口 404），**必须重启后端**才生效
