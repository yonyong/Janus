设计说明

对照现有实现（Workbench.tsx / WorkflowSteps.tsx）的重设计要点。数据与文案均为演示。

顶部区：一条横栏，步骤条整体移除

  • 顶部步骤条不再需要（本轮定稿）——阶段感知改由两处承载：头部小 chip「阶段：编码实现」+ 右侧流程指令清单的高亮状态。
  • 元信息（会话 / 项目 / Agent·分支）降为灰底小胶囊，从「一排彩色 Tag」退到视觉第二层，标题成为唯一焦点。
  • 标准 / 轻量模式切换保留在顶栏 Segmented 控件。

    • 左侧：固定文件区 = 竖向分类页签 + 横向子页签

  • 左栏不再随阶段整体切换，固定为文件区；四个分类做成竖向页签栏（最左一列：需求文档 / 用例 / 归档 / 项目文件，图标+文字，异常数打红角标）。
  • 分类内部再放横向子页签承载具体功能：需求文档 = 原始需求 / 详细设计 / 附件；用例 = 用例配置 / 草稿；归档 = 测试报告 / 其他；项目文件 = 文件树 / 改动。文档编写、用例配置这类操作都在子页签层完成。
  • 点击 .janus 规范文件打开预览弹层：需求/设计文档可编辑保存（含版本历史入口）；test-result.md 弹层顶部即归档验收操作条（验收通过 / 打回修改）+ 测试报告表——归档操作随文件走，不再需要独立页面。
  • 左栏仍支持拖拽调宽（300px ~ 62%）与一键收起。

    • 右侧：AI 对话面板 + 全流程指令清单

  • 对话面板上方新增「流程指令」清单（可收起）：全部指令跨阶段按推荐顺序连续编号（① 润色需求文档 → … → ⑥ 归档验收），每条一句话说明做什么。
  • 状态打标：✓ 已完成（绿）/建议下一步（蓝框高亮）/ 待执行；轻量模式下「需求澄清 / 用例配置」整组标可选 · 可跳过。
  • 点击指令即切换到对应阶段上下文并填入输入框；指令是否已完成由平台按产出自动判定（文档字数、用例数、测试报告表格等）。
  • 去重定稿：消息流里的「下一步引导卡」不再带跳转按钮，只做提示，统一以流程指令清单的高亮为唯一操作入口，避免两处按钮打架。

    • 对话区

  • Agent 回复改为卡片气泡：内嵌代码块、改动文件小卡片（文件名 + 增删行数）。
  • 「下一步引导」改为消息流内的引导卡（带「进入下一环节」按钮），跟上下文走。

    • 未动的部分（刻意保留）

  • 四阶段语义、阶段存储、轻量模式规则、中止逻辑、会话切换——全部不动，只换渲染形态。
  • Agent 对话链路（SSE、快捷指令话术、草稿自动导入）不变；文件区是只读视角的重组织，落码时复用 FilePane / FileViewer 既有能力。
